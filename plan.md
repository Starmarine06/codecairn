# Plan: shipping `ctxmap` (Rust) as an npm package

**Status: implemented.** The tool shipped as **`codecairn`** (name collision on `ctxmap`). Milestones 1-6 are done: binary-only Rust crate split into `src/{main,analyze,extract,format,resolve}.rs`, tree-sitter-first extraction with regex fallback (upgraded from regex-only), 30 unit tests green (`cargo test`), `cargo fmt --check` + `clippy -D warnings` clean, npm build/smoke loop (`npm run rebuild`) works, and CI (`release.yml`) builds all 7 targets, publishes platform npm packages then the main package, publishes to crates.io, and creates a GitHub Release. Two CI bugs were fixed during implementation: the version-stamp sed was rewriting `optionalDependencies` **keys** instead of bumping **values** (now verified against the real package.json), and the musl build step was missing `musl-tools`. The Alpine launcher detects musl upfront via `process.report.getReport().header` instead of fallback-on-missing-binary.

**Goal:** `npx ctxmap` (or `npm i -g ctxmap`) works on Linux, macOS and Windows with **no Rust toolchain installed**, and the tool itself stays 100% Rust.

---

## 1. Options compared

| Option | How it works | Pros | Cons | Verdict |
|---|---|---|---|---|
| **A. Prebuilt binaries via `optionalDependencies`** | One tiny main package + one package per platform holding the compiled binary. npm installs only the matching one. | No install scripts (works with `--ignore-scripts`, offline mirrors, corporate proxies). Fast. Proven by esbuild, Biome, SWC, Turbo. | More packages to publish (automated in CI). | **Recommended** |
| B. `postinstall` downloads binary | Main package downloads from GitHub Releases on install. | One npm package. | Breaks with `--ignore-scripts`, offline installs and locked-down networks. Security teams dislike it. | Fallback only |
| C. `napi-rs` native addon | Compile Rust to a `.node` module and call it from JS. | Gives a real JS API (`import { map } from 'ctxmap'`). | More complex build, ABI/Node-version concerns, and you'd write JS glue. | Only if a JS API is required |
| D. WebAssembly | Compile to WASM, run in Node. | One artifact for all platforms. | WASI filesystem access is awkward; slower; walking a real repo is the whole point of the tool. | Not suitable |
| E. `cargo install ctxmap` only | Publish to crates.io. | Trivial, Rust-native. | Requires Rust installed; not an "npm thing". | Do this **in addition** |

**Decision:** go with **A**, and also publish to crates.io (E) because it costs almost nothing.

**Note on "all code in Rust":** npm needs a small launcher script (~25 lines of JS) that finds the right binary and runs it. This is unavoidable with option A. Keep it dumb and never put logic in it.

| Rust target | npm package | `os` | `cpu` |
|---|---|---|---|
| `x86_64-unknown-linux-gnu` | `@ctxmap/linux-x64` | linux | x64 |
| `aarch64-unknown-linux-gnu` | `@ctxmap/linux-arm64` | linux | arm64 |
| `x86_64-unknown-linux-musl` | `@ctxmap/linux-x64-musl` | linux | x64 |
| `x86_64-apple-darwin` | `@ctxmap/darwin-x64` | darwin | x64 |
| `aarch64-apple-darwin` | `@ctxmap/darwin-arm64` | darwin | arm64 |
| `x86_64-pc-windows-msvc` | `@ctxmap/win32-x64` | win32 | x64 |
| `aarch64-pc-windows-msvc` | `@ctxmap/win32-arm64` | win32 | arm64 |

Start with the first, fourth, fifth and sixth (covers ~95% of users). Add the rest later.

> musl vs glibc: npm's `os`/`cpu` fields can't distinguish them. Detect at runtime in the launcher (check `process.report.getReport().header.glibcVersionRuntime`) and pick the `-musl` package on Alpine.

### Platform package `npm/platforms/darwin-arm64/package.json`


### Launcher `bin/ctxmap.js` (the only JS in the project)

```js
#!/usr/bin/env node
const { spawnSync } = require("child_process");
const key = `${process.platform}-${process.arch}`;
const exe = process.platform === "win32" ? "ctxmap.exe" : "ctxmap";
let bin;
try {
  bin = require.resolve(`@ctxmap/${key}/bin/${exe}`);
} catch {
  console.error(`ctxmap: no prebuilt binary for ${key}. Try: cargo install ctxmap`);
  process.exit(1);
}
const r = spawnSync(bin, process.argv.slice(2), { stdio: "inherit" });
process.exit(r.status ?? 1);
```

## 6. CI / release pipeline (GitHub Actions)

Trigger: push of a tag like `v0.1.0`.

1. **Verify:** `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`.
2. **Build matrix** (one job per target):
   - macOS x64/arm64 and Windows: native runners (`macos-13`, `macos-14`, `windows-latest`).
   - Linux x64: `ubuntu-latest`.
   - Linux arm64 / musl: `cargo zigbuild` or `cross`.
   - Each job runs `cargo build --release --target <triple>` and uploads the binary as an artifact.
3. **Smoke test each binary** on its own OS: `ctxmap --version` and run on the fixture project; diff against the golden output.
4. **Package:** a script downloads all artifacts, creates each `npm/platforms/<name>/` directory with the binary (`chmod 755`), stamps the tag's version into every `package.json`.
5. **Publish order matters:** platform packages first, main package last (so its `optionalDependencies` already exist).
   ```
   npm publish --access public --provenance   # for each platform package, then main
   ```
6. **Also:** `cargo publish` and create a GitHub Release with the raw binaries attached.

Use **npm trusted publishing (OIDC)** or a scoped automation token stored as a GitHub secret, and enable 2FA on the npm account.

## 9. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Package name `ctxmap` already taken | Check `npm view ctxmap` now; fall back to a scope, e.g. `@yourname/ctxmap` |
| Platform packages need an npm org/scope | Create the org (free for public packages) before the first publish |
| Executable bit lost on some installs | Launcher does a defensive `fs.chmodSync(bin, 0o755)` on non-Windows |
| macOS Gatekeeper warns about unsigned binary | Binaries fetched by npm are not quarantined, so this rarely appears; sign and notarize later if distributing raw downloads |
| Version drift between packages | CI stamps one version everywhere; a CI check fails if `Cargo.toml`, npm and tag differ |
| Heuristic import graph disappoints users | Keep the "heuristic" footer; consider tree-sitter in v0.2 |
